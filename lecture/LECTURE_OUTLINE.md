# LECTURE_OUTLINE.md — Структура лекции SRE по безопасности

**Тема:** «Как легко взламываются приложения и как легко найти дыры с помощью ИИ»
**Формат:** 45–60 минут, живая демонстрация на локальном полигоне
**Полигон:** FastAPI CRUD + SQLite (ozyab09/fast-api-audit) на `127.0.0.1:8000`

---

## Часть 1. Введение (5 мин)

- Миф: «моё приложение маленькое, никому не нужно»
- Реальность: сканеры и ИИ автоматизируют взлом — атакующему не нужен твой URL, ему нужен твой стек
- Статистика: время от публикации уязвимости до эксплойта (часы, не дни)
- **Слайд-хук:** «Сейчас я взломаю приложение за 3 минуты. У вас на глазах.»

---

## Часть 2. Живая демонстрация: «3 минуты до компромисса» (15 мин)

| Время | Действие | Что показывает |
|-------|----------|----------------|
| 0:00–0:30 | Запуск приложения | `uvicorn app.main:app` — обычное CRUD |
| 0:30–1:30 | Промпт ИИ: «найди уязвимости» (PROMPTS.md п.1) | ИИ находит SQLi за секунды |
| 1:30–2:30 | Промпт ИИ: «сгенерируй эксплойты» (п.2) | Готовые payload'ы из коробки |
| 2:30–3:00 | curl с экрана (PAYLOADS.md) | UNION читает схему БД |

**Ключевой кадр:** экран разделён — слева код с f-string, справа ответ ИИ с CWE-89 и curl.

## Часть 3. ИИ как инструмент атакующего (15 мин)

### 3.1 ИИ-фаззинг (живой скрипт)
```bash
python3 demo_ai_fuzz.py --target http://127.0.0.1:8000
```
- Скрипт гоняет 20+ вредоносных значений (NaN, переполнения, XSS, SQL)
- Находит 500-ки → показывает, где валидация не отработала

### 3.2 Сканер + ИИ-объяснение
- `bandit -r app/` → сырой список
- Prompt «объясни, что критично» (PROMPTS.md п.4)
- Вывод: ИИ превращает шум CVE в action plan

### 3.3 Supply chain
- `pip-audit` → куча CVE
- ИИ объясняет: какие системные, какие реально достижимы
- Вывод: не паникуй по всему списку, приоритизируй

---

## Часть 4. ИИ как новая поверхность атаки (10 мин)

- **Prompt injection:** пользователь переопределяет системный промпт
  - Пример: «Ignore all previous instructions...»
  - Демо прямо из чата (если есть AI-фича в приложении)
- **Секреты в репо:** gitleaks находит токен → ИИ объясняет, что делать
- **ИИ-агенты** (auto-GPT, MCP): если агенту дать доступ к инструментам, инъекция = компромисс инфраструктуры
- Вывод: SRE обязан знать и защищать AI-компоненты как часть периметра

---

## Часть 5. «ИИ против ИИ» + ограничения (5 мин)

- Один код двум моделям → сравнить отчёты (находят разное!)
- Ограничения ИИ: галлюцинации, устаревшие знания, отсутствие контекста
- Вывод: ИИ ускоряет, человек решает. Нужен контур проверки (review, тесты, sandbox)

---

## Часть 6. Чек-лист защиты (5 мин)

Раздать всем:
- Параметризованные SQL / ORM
- Валидация входа (Pydantic, allow_inf_nan=False)
- Аутентификация + роли
- CORS allowlist, security-заголовки, закрыть /docs в проде
- Rate limiting
- SAST/DAST в CI (bandit, semgrep, trivy) + LLM-ревью как дополнение
