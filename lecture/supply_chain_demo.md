# Supply-chain демо (п.4): как «безобидный» pip-пакет может навредить

> Учебный материал. Мы НЕ публикуем вредоносный пакет.
> Вместо этого показываем механизм на **локальном** пакете и разборе механизма.

---

## Концепция демо

`pip install <пакет>` = **запуск кода от имени пакета**. Любой `install` может выполнить payload ещё до того, как ты его используешь (через `setup.py`, `__init__.py`).

## Часть 1. Механизм (безопасно, локально)

Создаём учебный пакет, который при импорте делает безобидное доказательство (пишет файл):

```python
# /tmp/innocent_pkg/innocent_pkg/__init__.py
print("[!] import happened — код выполняется при импорте!")
open("/tmp/supply_chain_proof.txt", "w").write("это доказательство выполнения кода")
```

```bash
cd /tmp/innocent_pkg
pip install -e .          # ставим
python -c "import innocent_pkg"   # ← при импорте сработал print + записал файл
cat /tmp/supply_chain_proof.txt   # ← файл создан = код выполнен
```

**Вывод:** если бы вместо `print` был `os.system("curl ... | sh")` — произошла бы компиляция/утечка. Код пакета — **это код, который исполняется с правами запустившего**.

## Часть 2. Реальный граф зависимостей

Показать, насколько широка поверхность:

```bash
# сколько всего ставится для fastapi?
pip install fastapi ucivorn
pip show fastapi   # + зависимости
pip-audit          # какие из них имеют CVE
```

Недавно проверили нашим проектом:
- `pip-audit` нашёл уязвимости в **системных** setuptools/urllib3/twisted (вне проекта).
- Зависимости приложения (fastapi, uvicorn, starlette, pydantic) — **чисты**.

**Вывод:** supply chain — это не только «твои» пакеты, но и **транзитивные** + их версии + доверие к PyPI/зеркалам.

## Часть 3. Угрозы, которые стоит упомянуть

| Угроза | Как работает | Как защититься |
|--------|--------------|----------------|
| Malicious package | пакет с красивым именем, payload в setup.py | проверять репутацию, `pip install --dry-run`, sandbox |
| Typosquatting | `pandaas`, `fastapi-utils` (похоже на популярный) | точное имя, hash, из официального индекса |
| Supply chain компромисс | взломали пакет, новый релиз с бэкдором | pin версии, `--require-hashes`, verify |
| Транзитивные | зависимость зависимости | `pip-audit`, `pip check`, lock-файл |

## Вывод для слайда

> `pip install` — это запуск чужого кода на твоей машине/в проде.
> Доверяешь PyPI — но проверяй: `pip-audit`, `pip check`, pin, `--require-hashes`,
> сканируй SBoM (trivy, syft). ИИ ускоряет чтение CVE-списков и разбор графа.
